# План Angular для каталога и офлайн-чтения «Кадра»

Реализация выполнена. Итоговый контракт и результаты приёмки приведены в [отчёте](catalog-and-offline-report.md). Разделы ниже сохраняют исходный план.

Согласованный контракт реализации берётся из [backend-плана](../../backend/docs/catalog-and-offline-plan.md). В URL используются повторяемый `tagId` и значения `relevance`, `year_asc`, `year_desc`, `latest_chapter_desc`. Список использует `/library/downloads`, локальное чтение — `/downloads/:id/read`. Скачиваемые состояния включают `DELETING`, а неподходящие теги выделяются по `invalidTagIds`.

Документ описывает два этапа. Сначала теги, фильтрация и поиск в каталоге выбранного источника. Затем скачанные главы Pepper&Carrot. Нового backend-плана для этих функций в репозитории пока нет. За основу взяты текущий код Angular и [REST-контракт](../../backend/README.md#контракт-api). Новые параметры, поля и маршруты ниже предложены для согласования с бэкендом.

## Этап 1. Теги и поиск по источнику

### Карточка тайтла

- Под описанием MangaDex показать раздел «Теги» со ссылками в виде компактных плашек. Показывать название из API для текущего RU/EN. Если его нет, показывать другое доступное название. Ключ плашки и значение фильтра — ID тега. Переключение RU/EN меняет подпись, сохраняя ID, URL и результаты.
- Тег оформляется ссылкой на `/catalog?sourceId=mangadex&tagId=…` с применённым фильтром. Пустой массив тегов скрывает раздел. Сбой загрузки списка тегов каталога не влияет на карточку, которая получает свои теги в `TitleDetail`.
- При переходе из выдачи в карточку сохранить контекст каталога для ссылки «В каталог». Передавать только нормализованные параметры внутреннего маршрута, составлять ссылку через Angular Router. При прямом открытии тайтла возврат ведёт в каталог его источника.

### Каталог

- Оставить поле поиска рядом с переключателем источника. Для выбранного источника показать «Поиск в MangaDex» или его фактическое имя из API. Для режима без фильтра по источнику — «Поиск по всем источникам».
- Для MangaDex разместить рядом «Теги» с количеством выбранных и «Сортировка». В панели тегов сгруппировать элементы по группе из API, использовать чекбоксы и подпись «Все выбранные теги». Выбранные теги показать съёмными плашками. Кнопка «Сбросить теги» очищает только теги. Кнопка «Сбросить поиск и фильтры» убирает запрос, теги и сортировку, оставляя выбранный источник.
- Сортировки MVP — «По умолчанию», «По релевантности», «Сначала новые по году» и «По последней добавленной главе». Релевантность доступна для непустого `q`. При очистке запроса с этой сортировкой вернуть вариант по умолчанию. Конкретные доступные значения согласовать с backend.
- Список источников по-прежнему приходит из `GET /api/v1/sources`. Для источника без поддерживаемых опций оставить поиск, скрыть теги и неподдерживаемые варианты сортировки. При смене источника сохранять текст запроса, очищать теги старого источника и возвращать сортировку по умолчанию. В режиме «Все источники» применять лишь общий поиск. Для прямой ссылки с отключённым источником использовать существующее состояние `SOURCE_DISABLED` и действие «Все источники».
- У списка тегов предусмотреть собственную загрузку, ошибку и повтор. При ошибке выдачи сохранить запрос и фильтры. При пустой выдаче с фильтрами показать «Ничего не найдено» и сброс. При отсутствии подключений оставить переход в «Обзор». Пустая выдача и ошибка API имеют отдельные состояния.
- Использовать существующие цвета, `button`, `surface`, `status-tag` и `app-state`. На ширине 390 px контролы и плашки переносятся на следующие строки. Панель фильтров доступна с клавиатуры. Если это диалог, Escape закрывает его, а фокус возвращается к кнопке открытия.

### URL и запросы

- URL задаёт применённое состояние. Пример — `/catalog?sourceId=mangadex&q=Frieren&tagId=<uuid1>&tagId=<uuid2>&sort=year-desc`. `tagId` повторяется для каждого тега. Значения по умолчанию и пустой запрос опускаются из URL. Повторные ID удаляются и кодируются через Angular Router.
- Сохранить задержку поиска около 220 мс. Поле ввода хранит черновик, а запрос к API строится по применённому URL после задержки. Частые правки текста используют замену записи истории. Явные изменения источника, тегов, сортировки и сброс создают запись истории. Поле ввода и выборы восстанавливаются из URL при обновлении, «Назад» и «Вперёд». При навигации отменять отложенную запись старого черновика. При явном применении фильтров включать текущий черновик, чтобы не потерять только что введённый поиск.
- Расширить `Api.catalog` объектом параметров и передавать повторяющиеся теги через `HttpParams`. Сохранить серверную выдачу, текущую сетку и независимую ленивую загрузку счётчиков. Angular показывает порядок ответа API. Сервер применяет поиск, фильтры и сортировку до лимита выдачи.
- Прямую ссылку с синтаксически неверными параметрами нормализовать без лишней записи истории. Если сервер вернул ошибку для неизвестного или неподдерживаемого тега, сохранить остальную комбинацию и дать убрать ошибочный фильтр. Ошибка загрузки справочника сама по себе не должна удалять валидные ID из ссылки.

### Зависимости от backend

| Предложение | Что требуется согласовать |
| --- | --- |
| `TitleDetail.tags: Tag[]` | `Tag` содержит `id`, `group` и локализованные `names`. Для тайтла без тегов приходит пустой массив. |
| `GET /api/v1/sources/{sourceId}/tags` | Список тегов выбранного источника отдельно от ограниченной выдачи каталога. Согласовать, как сообщаются поддерживаемые возможности источника и срок кеша справочника. |
| `GET /api/v1/catalog?sourceId=…&q=…&tagId=…&sort=…` | Повторяющийся `tagId`, правило AND, список сортировок, поведение по умолчанию, форма ошибок для неизвестных тегов и неподдерживаемых комбинаций. Например, `relevance`, `year-desc`, `latest-chapter`. |

## Этап 2. Офлайн-чтение Pepper&Carrot

### Экраны и сценарии

1. **Карточка тайтла.** Рядом с действиями чтения главы добавить «Скачать главу». Если переводов несколько, открывать выбор языка по `chapter.languages`. При одном переводе показывать его в действии и сразу отправлять запрос. Использовать возможности из API для определения того, где скачивание доступно. В MVP оно доступно для Pepper&Carrot.
2. **Состояния по главе и языку.** Показать «В очереди», ход загрузки, «Скачано», ошибку и «Повторить». Если сервер сообщает число страниц, показать прогресс «X из Y», иначе — индикатор ожидания. Кнопка занята на время запроса. «Читать офлайн» и отметка «Скачано» появляются после подтверждённого `READY`. Отметка относится к конкретному переводу. После ошибки повторы используют ту же запись, чтобы один перевод не появлялся в списке дважды.
3. **Библиотека и «Скачанное».** Добавить ссылку из библиотеки на `/library/downloads` в существующей навигации. Этот экран показывает отдельно загруженные, скачиваемые и ошибочные главы из локального API, с названием тайтла, номером главы и языком. Доступны «Читать офлайн», «Повторить» и «Удалить загрузку» в соответствующих состояниях. Удаление подтверждается и убирает локальную копию главы после ответа API. Статус, заметка и прогресс в библиотеке независимы от загрузок.
4. **Читалка.** Ссылки «Читать офлайн» используют существующий маршрут `/read/…` с предложенным `?downloadId=…`. Для него читалка получает локальный манифест с метаданными и ссылками страниц Spring Boot, переиспользует `PageImage`, счётчик и блок атрибуции. Диалог глав и переходы ведут к доступным локальным переводам. Возврат ведёт в «Скачанное». Если локальная запись пропала или файл повреждён, показать причину и путь назад в список. Онлайн-переход возможен отдельным действием, когда доступен источник.

### Состояние и границы офлайна

- Состояние загрузки принадлежит Spring Boot. Angular считывает его при открытии экранов и периодически обновляет активные задачи, пока открыт соответствующий экран. Уведомления и переходы отражают серверные ответы. После перезапуска страницу можно открыть заново и получить подтверждённое состояние из локального API.
- Идентичность копии — `sourceId + externalTitleId + chapterId + language`. Язык интерфейса RU/EN и язык скачанного перевода управляются независимо.
- Локальный режим читает метаданные тайтла и главы, список страниц, обложку при наличии и атрибуцию из локальных ответов. При открытии скачанной главы не запускать текущие онлайн-ресурсы `title()`, `chapters()` и `pages()` параллельно. При недоступности списка глав источника локальный раздел «Скачанные главы» остаётся доступен из карточки или через «Скачанное».
- Офлайн означает работающие локальные Angular, Spring Boot и PostgreSQL с заранее подготовленными ресурсами при отключённом внешнем интернете. Изображения отдаёт локальный сервер. Фронтенд загружает UI и словари с локального хоста. Отдельный режим с выключенным локальным сервером в MVP не входит.
- Параметр `page` можно использовать для уже сохранённой закладки, если она относится к той же главе и языку. Сохранение новой позиции офлайн требует проверки по локальному манифесту на бэкенде. Сейчас `PATCH /library/{id}` проверяет позицию через адаптер, поэтому эту возможность нужно явно согласовать.

### Зависимости от backend

| Предложение | Ожидаемое поведение |
| --- | --- |
| `GET /api/v1/downloads`, опционально по тайтлу | Локальный список с ID, идентичностью перевода, статусом, прогрессом и краткими метаданными. Доступен после рестарта при недоступности Pepper&Carrot. |
| `POST /api/v1/downloads`, действие повтора и `DELETE /api/v1/downloads/{id}` | Асинхронный запуск и повтор без дубликата по ключу главы и языка. Согласовать статусы `QUEUED`, `DOWNLOADING`, `READY`, `FAILED`, поля прогресса и разрешённые действия для каждого состояния. |
| Локальный манифест главы, например `GET /api/v1/downloads/{id}/pages` | Локальные метаданные тайтла и структура `ChapterPages` с порядком изображений, атрибуцией и ссылками Spring Boot. Для полностью загруженной копии страницы и список локальных соседей не требуют внешнего API. |
| Возможность офлайн-скачивания | Сервер сообщает поддержку по источнику или тайтлу. В MVP Pepper&Carrot включён, MangaDex по-прежнему читается онлайн. |

## Порядок и приёмка

1. Согласовать с backend поля DTO, поддержку сортировок и ошибки. Этап каталога начинать после согласования каталожного API, этап скачиваний — после согласования локального манифеста и жизненного цикла задачи.
2. На живом API открыть «Обзор → MangaDex → каталог», выполнить поиск с несколькими тегами, переключить сортировку и подтвердить, что ответы соответствуют параметрам. Кликнуть на тег в карточке, проверить ссылку и фильтр. Проверить перезагрузку, возврат из карточки, «Назад/Вперёд», переключение источников, RU/EN для тега с переводом и без него, пустой результат и ошибки. Для Pepper&Carrot и «Все источники» проверить обычный поиск без тегов.
3. Скачать один перевод главы Pepper&Carrot. Убедиться, что второй язык остаётся в собственном состоянии. Воспроизвести неуспешную загрузку и повтор, проверить появление «Скачано» только после `READY` и отсутствие дубликата. Проверить удаление скачанной копии и сохранение записи в библиотеке.
4. Перезапустить локальные сервисы после успешной загрузки, оставить localhost доступным и отключить внешний интернет. В новом сеансе браузера открыть `/library/downloads`, затем скачанную ранее главу, дойти до последней страницы и проверить порядок, язык и титры. По запросам браузера подтвердить, что метаданные и изображения этой главы идут через локальные URL. Для соседней несохранённой главы проверить понятное состояние недоступности.
5. После реализации запустить `npm run build` и пройти сценарии на 390 и 1440 px с клавиатурой и видимым фокусом. Этот документ фиксирует предстоящие проверки, результаты проверок будут записаны после реализации.
