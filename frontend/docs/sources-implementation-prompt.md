# Промпт для frontend-модели

Доработай Angular-приложение «Кадр» в `frontend/`. Изучи `frontend/README.md`, маршруты в `src/app/app.ts`, клиент в `api.ts`, каталог, общие компоненты состояний и `src/styles.css`. Используй контракт ниже и сверяйся с `backend/README.md`.

## Порядок работы

1. До изменений приложения создай `frontend/docs/sources-implementation-plan.md`. Опиши текущий поток каталога, маршрут, вкладки, модель данных, состояния, доступность и сценарии проверки.
2. После сохранения плана реализуй изменения в существующем проекте. Проверь работу в браузере с живым Spring Boot API и запусти `npm run build` из `frontend/`.
3. Создай `frontend/docs/sources-implementation-report.md`. Запиши реализацию, команды, фактические результаты, отклонения от плана и оставшиеся проверки. Обнови `frontend/README.md` и добавь ссылки на план и отчёт. Сохрани кадры обеих вкладок на 390 и 1440 px в `frontend/docs/screenshots/` и приложи их к отчёту.

## Что реализовать

- Добавь раздел «Обзор» с маршрутом `/browse` и входом из основной навигации. Внутри две вкладки — «Источники» и «Расширения». По умолчанию открывай «Источники». Из референса возьми идею вкладок. Для визуального оформления используй текущий стиль «Кадра», графитовый фон, светлый текст и существующий акцент. Вкладка Migrate в задачу не входит.
- В «Расширениях» покажи сайты из `GET /api/v1/extensions` с названием и состоянием. Для доступного сайта покажи «Подключить», для активного — «Подключено». В «Источниках» покажи подключения из `GET /api/v1/sources`. Из строки можно открыть каталог с выбранным источником или отключить его. Для пустого списка добавь переход в «Расширения».
- Используй относительные запросы через существующий dev proxy. Актуализируй обе вкладки по ответам API после изменения. На время запроса блокируй повторное действие по тому же источнику. При ошибке сохраняй последнее подтверждённое состояние, показывай сообщение и снова разрешай действие. Добавь состояния загрузки, пустого списка и ошибки.
- Переведи фильтр каталога на `GET /api/v1/sources`. Поддержи прямой вход по `/catalog?sourceId=…`, синхронизируй URL и фильтр, сохрани поиск по `q`. При `SOURCE_DISABLED` покажи сообщение и возможность сбросить фильтр. При отсутствии подключений предложи открыть «Обзор».
- Сохрани русский интерфейс, клавиатурную навигацию, видимый фокус, адаптивную компоновку и `prefers-reduced-motion`. Все файлы фронтенда держи внутри `frontend/`.

## Общий REST-контракт

| Запрос | Успешный ответ |
| --- | --- |
| `GET /api/v1/extensions` | `200 { "items": Extension[] }` — все зарегистрированные адаптеры. |
| `GET /api/v1/sources` | `200 { "items": Source[] }` — только подключённые. |
| `PUT /api/v1/sources/{sourceId}` без тела | Подключает известный адаптер. Возвращает `200 Source` при первом и повторном запросе. |
| `DELETE /api/v1/sources/{sourceId}` | Отключает известный адаптер. Возвращает `204` при первом и повторном запросе. |

`Source = { sourceId: string; sourceName: string; websiteUrl: string | null }`.
`Extension = Source & { enabled: boolean }`.

Неизвестный ID даёт `404 SOURCE_NOT_FOUND`. Ошибки используют существующий формат `application/problem+json`. Каталог `GET /api/v1/catalog` сохраняет параметры `q` и `sourceId`, ищет только по подключённым источникам и возвращает `{"items":[]}`, если подключений нет. Запрос каталога с известным отключённым `sourceId` даёт `409 SOURCE_DISABLED`. Маршруты карточек, глав, страниц и операции библиотеки сохраняют текущее поведение. Так читатель может продолжить сохранённое чтение после отключения источника из каталога.

Состояние подключений общее для локального экземпляра API. При обновлении или чистом запуске Pepper&Carrot первоначально подключён. Пользователь может отключить и снова подключить его.

## Приёмка

На живом API проверь обе вкладки, отключение Pepper&Carrot, пустой список, повторное подключение, вход в каталог с фильтром и сохранение состояния после обновления вкладки. Воспроизведи ошибку изменения и проверь возврат кнопки в рабочее состояние. Проверь карточку, главу и библиотеку. По окончании верни исходное состояние подключения. Если новый API ещё не доступен, реализуй клиент по контракту и укажи в отчёте, какие сценарии требуют живой интеграции.
