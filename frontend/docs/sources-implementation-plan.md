# План реализации раздела «Обзор»

## Исходное состояние

Каталог загружает полный список тайтлов, извлекает из него источники и передаёт `q` и `sourceId` в отдельный отфильтрованный запрос. Выбранный источник хранится в компоненте. Живой Spring Boot уже возвращает `200` для `GET /api/v1/sources` и `GET /api/v1/extensions`. Исходное состояние Pepper&Carrot — подключён.

## Изменения

1. Добавить Angular-маршрут `/browse` и ссылку в основную навигацию. Сохранить стиль «Кадра» и подвижную плашку навигации. На узком экране разместить основную навигацию под логотипом.
2. Сделать вкладки «Источники» и «Расширения» с состоянием в URL, поддержкой стрелок, Home и End, видимым фокусом и отдельными состояниями загрузки, ошибки и пустого списка. Во вкладке «Источники» добавить вход в отфильтрованный каталог и отключение. Во вкладке «Расширения» показать состояние и подключение.
3. Добавить типы и методы HTTP-клиента для обоих списков, PUT и DELETE. Блокировать параллельные действия по одному ID. Менять отображение после успешного ответа, обновлять оба списка и сохранять подтверждённые данные при ошибке. Показывать сообщение рядом с соответствующим источником.
4. Загружать варианты фильтра каталога из `GET /api/v1/sources`, привязать выбранный ID к query-параметру маршрута. Сохранить поиск с задержкой и относительные запросы. Обработать отключённый источник и пустой список подключений.

## Проверки

Собрать Angular. В браузере проверить обе вкладки, управление с клавиатуры, отключение и пустой список, обновление вкладки, подключение, переход в каталог, прямой URL, поиск, карточку, главу и библиотеку. Для проверки отказа изменения временно вернуть ошибку только на запрос подключения в отдельном локальном тестовом прокси, если живой API в штатном состоянии отвечает успешно. По завершении проверить исходное состояние подключения. Сохранить четыре скриншота на ширинах 390 и 1440 px и записать результаты в Markdown.
