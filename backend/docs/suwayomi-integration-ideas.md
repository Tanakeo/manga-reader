# Идеи Suwayomi для «Кадра»

Дата исследования: 22 ноября 2026 года. Статус: предложения, новые интеграции не реализованы.

Проверены Suwayomi-Server, Suwayomi-WebUI, документация локального источника и расширений, исходники загрузчика расширений, обновления библиотеки, очереди скачивания, читалки и переноса между источниками. Сопоставление с «Кадром» сделано по текущему коду, а не по прежним отчётам. Live-проверка Suwayomi и его расширений в это исследование не входит.

Для серверной архитектуры проверен commit `4081b05f02456ec099c85127dfa5253e968d48a7`. Ссылки на master отражают просмотренную версию на дату исследования и могут измениться.

## Что уже есть у нас

- Общий [MangaSource](../src/main/java/io/github/mangareader/source/MangaSource.java) и отдельные адаптеры MangaDex, MangaLib, MangaKakalot и Pepper&Carrot. Реестр создаётся из Spring-компонентов, произвольные внешние расширения он пока не загружает.
- [Локальный каталог](../src/main/java/io/github/mangareader/catalog/LocalCatalogService.java), состояния проверки глав и [фоновая синхронизация](../src/main/java/io/github/mangareader/catalog/CatalogSyncService.java). Планировщик повторно проверяет сохранённые тайтлы, но отдельной пользовательской ленты новых глав нет.
- Библиотека со статусом, заметкой, одной текущей [позицией чтения](../src/main/java/io/github/mangareader/library/LibraryModels.java) и пользовательскими секциями. Это ещё не история чтения и не прочитанность каждой главы.
- Вертикальная [читалка](../../frontend/src/app/reader.ts), lazy loading, blob-изображения, ограничение параллельных запросов, выбор главы и переходы. Сохранение позиции в компоненте привязано к офлайн-главе и выполняется отдельным действием. Полноценного автоматического сохранения онлайн-чтения нет.
- [Скачивание Pepper&Carrot](../src/main/java/io/github/mangareader/download/DownloadService.java), повтор, удаление и чтение локальных файлов. После перезапуска незавершённая загрузка помечается как прерванная. Паузу, изменение очередности и продолжение с уже проверенных страниц предстоит добавить.

| Обновления библиотеки | Лента «В ваших тайтлах появились новые главы», счётчик непрочитанного | Приоритет проверок для библиотеки, фиксация впервые обнаруженного выпуска и журнал обновлений. Использовать имеющуюся очередь, отделять время обнаружения от даты публикации источника. | Средняя |
| Настройки читалки | Ширина страницы, Webtoon/постраничный режим, направление справа налево, клавиши, скрытие панелей | Настройки устройства и переопределения для тайтла. Сначала ширина, режим и клавиши, затем развороты и автопрокрутка. Переиспользовать существующую загрузку изображений. | От небольшой до средней |
| Предзагрузка | Меньше ожидания при переходе вперёд | Ограниченное окно следующих страниц, отмена устаревших запросов и освобождение blob URL. У нас уже есть lazy loading, поэтому расширять его, не загружать главу целиком без необходимости. | Средняя |

| Перенос между источниками | При отказе сайта найти тот же тайтл на другом и сохранить библиотечные данные | Предпросмотр кандидатов, подтверждение соответствия, перенос статуса, заметки и секций. Главы сопоставлять по тому, номеру и языку. Точную страницу между разными переводами автоматически не переносить. | Высокая |
| Расширенная очередь скачивания | Пауза, продолжение, порядок, повтор только неудачных страниц | Дополнить существующую очередь и учёт файлов. Сначала Pepper&Carrot. Поддержку других источников включать отдельно после проверки доступности и условий. | Средняя |

## Как использовать готовые расширения

Это отдельная архитектурная возможность. Предлагаемая схема:

```text
Angular → Spring Boot «Кадра» → Suwayomi API → установленное расширение → сайт
                      ↓
              PostgreSQL «Кадра»
```

Suwayomi запускается отдельным сервисом. Наш backend переводит его ответы в существующие DTO. Библиотека, заметки, пользовательские секции, прогресс и локальная выдача каталога остаются под управлением «Кадра». Это предложение интеграции, а не уже готовое подключение.

Почему вариант реалистичен: Suwayomi предоставляет GraphQL для источников и получения данных, а его загрузчик умеет устанавливать пакеты расширений. Установка репозитория расширений выполняется отдельно — готового набора всех сайтов по умолчанию документация не обещает. [SourceQuery](https://github.com/Suwayomi/Suwayomi-Server/blob/master/server/src/main/kotlin/suwayomi/tachidesk/graphql/queries/SourceQuery.kt), [SourceMutation](https://github.com/Suwayomi/Suwayomi-Server/blob/master/server/src/main/kotlin/suwayomi/tachidesk/graphql/mutations/SourceMutation.kt), [Extension.kt](https://github.com/Suwayomi/Suwayomi-Server/blob/4081b05f02456ec099c85127dfa5253e968d48a7/server/src/main/kotlin/suwayomi/tachidesk/manga/impl/extension/Extension.kt), [Getting Extensions](https://github.com/Suwayomi/Suwayomi-Server/blob/master/docs/Getting-Extensions.md).

Предлагаемые части реализации:

1. `SuwayomiClient`: адрес сервиса из конфигурации, авторизация выбранной версии, таймауты и перевод ошибок. Проверить реальную GraphQL-схему запущенного сервера до фиксации запросов.
2. Общая реализация адаптера, настраиваемая ID источника расширения. Например, локальный `sourceId=suwayomi-<sourceId>`. Для нескольких экземпляров Suwayomi включить в идентичность настроенный ID экземпляра.
3. Расширение `MangaSourceRegistry`: сейчас это неизменяемая карта Spring-компонентов. Для динамического списка сайтов понадобится фабрика экземпляров или отдельный реестр провайдера.
4. Хранение соответствия стабильного ключа тайтла источника и внутреннего ID Suwayomi. Нельзя делать библиотеку зависимой только от автоинкрементного ID его БД.
5. Изображения через backend: проверенный источник, глава и индекс страницы. Доступность списка URL проверять отдельно от фактической загрузки файлов.
6. Сохранить отчёт о покрытии нашего каталога. Пагинация popular/search у расширения сама по себе не доказывает возможность перечислить весь каталог сайта. Неподдерживаемый полный обход должен явно оставаться частичным.

Плюсы: меньше собственных парсеров, обновления расширений независимо от выпуска «Кадра», возможность подключать дополнительные сайты через один общий клиент. Издержки: ещё один сервис, его данные и версии, авторизация, сопоставление ID и диагностика двух уровней API. Доступность MangaKakalot/MangaLib этим способом ещё предстоит измерить. Расширение не гарантирует устранение внешнего 403 или доступ ко всему корпусу.

Встраивать весь runtime расширений непосредственно в Spring Boot существенно сложнее. Код загрузчика работает с Android-совместимыми API, метаданными пакетов и преобразованием APK, а не только с HTTP-парсерами. Для курсовой отдельный сервис выглядит более управляемым вариантом. ## Общие адаптеры без дополнительного сервиса

Если оставаться на собственных адаптерах, сохранять общий `MangaSource` и выделять семейства похожих сайтов. Общими могут быть HTTP-клиент, пагинация, извлечение HTML-карточек и проверка изображений. Селекторы, JSON-пути, заголовки, правила веток переводов и допустимые домены задаются адаптером семейства и конфигурацией конкретного сайта.

Один общий Java-клиент к Suwayomi действительно может обслуживать много источников. Один универсальный HTML-парсер для любых сайтов потребует постоянно растущих исключений. Интерфейс Suwayomi тоже разделяет популярные тайтлы, поиск, обновления, обновление карточки/глав и страницы. [Source.kt](https://github.com/Suwayomi/Suwayomi-Server/blob/4081b05f02456ec099c85127dfa5253e968d48a7/server/src/main/kotlin/eu/kanade/tachiyomi/source/Source.kt)

## Рекомендуемая последовательность

1. Автопрогресс и история чтения.
2. Лента новых глав библиотеки на существующих очередях.
3. Настройки читалки: ширина, направление, режим, клавиши.
4. Локальный источник с папками и CBZ — удобный независимый сценарий для демонстрации курсовой.
5. Отдельный эксперимент Suwayomi: один источник, несколько глав, реальные изображения, отказ и перезапуск. После успешного эксперимента решать вопрос массового подключения.
6. Перенос между источниками, расширенная очередь, резервная копия и пакетные действия.

Внешние трекеры AniList/MyAnimeList доступны в экосистеме Suwayomi, но для ближайшего этапа курсовой добавят OAuth, внешние идентификаторы и разрешение конфликтов прогресса. Их разумно рассматривать после локального прогресса и резервного копирования. [Возможности сервера](https://github.com/Suwayomi/Suwayomi-Server#features)

WebUI использует React, MUI и Apollo. Его TSX-компоненты потребуют адаптации под Angular. Для первого этапа разумно перенести поведение и модели своим кодом. Server и WebUI опубликованы под MPL-2.0, при прямом переиспользовании файлов учитывать их лицензию, а лицензии расширений проверять отдельно.
