# Автопрогресс и история чтения «Кадра»

Этап 1 реализован. История открывается из библиотеки по ссылке «История чтения» или по маршруту `/library/history`. Кнопка «Продолжить» в библиотеке, на странице тайтла и в истории открывает сохранённый выпуск и перевод. При наличии готовой копии можно продолжить офлайн.

Позиция сохраняется после того, как декодированная страница видна в области чтения примерно секунду. Текущая позиция может двигаться назад. Просмотренные страницы и прочитанность выпуска хранятся отдельно. Автоматическая отметка требует всех страниц и двух секунд видимости конца последней. Ручная отметка доступна в списке глав и истории. Статус тайтла определяется в библиотеке.

## Запуск и данные

Команды запуска приложения находятся в [README проекта](../../README.md). Spring Boot применяет V14 автоматически. Миграция переносит существующую позицию и создаёт запись истории с происхождением LEGACY. Время такой записи приближённое. Состояние библиотеки, заметки и секции сохраняются. Скачанные главы читаются без внешнего интернета при работающих локальных сервисах.

Контракт приводится в [плане этапа](reading-progress-plan.md). Реализация использует пакет `library` и сервис `ReadingService`, который разделяет транзакции с редактированием библиотеки. Запись сверяет главу и размер манифеста с сохранёнными сервером данными. Онлайн-манифесты сравниваются по версии для конкретной записи и по упорядоченным путям страниц для объединения просмотра между загрузками. Общая позиция выпуска для онлайн и готовой копии использует тот же индекс для совпадающего набора страниц.

Backend хранит активную сессию тайтла и проверяет ревизию и порядковый номер события. Повтор с тем же eventId получает актуальный ответ без повторной записи. При конфликте читалка предлагает принять серверную или локальную позицию. IndexedDB хранит ещё не подтверждённое событие и ожидающие изменения. Приложение пытается отправить их при выходе из читалки и повторяет после сетевого сбоя или повторного открытия. Время просмотра приблизительное.

Ручная установка или очистка позиции через `PATCH /api/v1/library/{id}` требует `expectedReadingRevision` из текущего ответа библиотеки. Ответ сохраняет прежний объект `progress` и добавляет `readingRevision`. PATCH заметки или статуса работает в прежнем формате.

## Фактические проверки

- PostgreSQL V13 → V14 на отдельной базе с прежней позицией, заметкой, статусом и секцией. Проверены сохранённый индекс и состав секции.
- Прошли все 25 тестов backend, включая возврат на меньший индекс, повтор одного события, отклонение вытесненной сессии и ручной сброс прочитанности.
- Production-сборка Angular прошла.
- Edge 1440 и 390 px с живым Spring Boot API. Pepper&Carrot онлайн на русском и скачанный выпуск на английском. Проверены реальные изображения, ошибка и повтор, переход на меньший индекс, кнопка следующей главы, восстановление позиции после открытия, ссылки из библиотеки и тайтла, история и независимость статуса. При принудительном отказе PUT очередь пережила перезагрузку и отправила позицию, когда запросы снова стали возможны.
- Смена сессий проверена по HTTP в интеграционном тесте. Браузерный прогон использовал Pepper&Carrot, а другие источники и сочетания браузеров отдельно не проверялись.
